## 用户与场景

第一用户是已经读过一篇方法型知乎内容、准备真正照着做的人。具体人群与题材由官方内容池决定，不在产品层预先固定。

核心痛点不是缺答案，而是执行静态知识时必须反复找步骤、记状态、防遗漏，且 AI 新生成的建议很难确认是否忠于原文。

## 一句话定位

> 把真实知乎知识自动编译成可运行、可回看原文依据、可留下结果的互动程序。

这里的“Run”不是文章清单：用户的有效操作必须改变一个可见的程序状态、路径或结果物。

## Hero

- Grammar：后端根据真实内容的规则、条件、动作与反馈，在七种声明式运行模型中选择；用户不需要、也不会选择模型名。至少形成两种明显不同的运行体验。
- 具体 Source：Hero 使用已确认完整的知乎 Full Source；Supporting Run 可使用赛事官方详情接口返回、覆盖范围明确的 Bounded Source Excerpt。完整来源可以是赛事详情接口，或知乎创作分析接口为当前 Access Secret 所属账号返回的本人全文。不得让预设题材反过来强行适配文章。
- Hero Moment：用户在一篇知乎知识或赛事模拟知识上点击“用一下”，直接运行由该文章编译出的程序；完成后看到本次 Result，并能一键回看原文依据。
- 失败降级：实时内容或 LLM 不可用时，已发布 Hero 仍能完整运行；真实来源与赛事模拟知识必须分开标识，不能把模拟内容称为官方接口返回的真实正文。

## P0

1. Official Source Provider、赛事模拟知识目录、完整性识别与 Source Scope 门禁。
2. AI Judge、Programability Judge、Planner、Compiler、Schema Validator、Source Anchor Validator 与必要的确定性 Evaluator。
3. 受保护的内部 Preview/Publish 流程；不要求完整 Admin UI。
4. 产品层只使用三套运行引擎：路径模拟、微型实验、规则沙盘。内部可用情境、诊断、行动编排、对话、参数等声明式子模型表达差异，但它们不构成用户可见的七种产品类型。真实内容只可选择其原文确实支持的结构；至少两种明显不同的体验进入最终 Published Run。
5. 发现、我的、详情、运行、Result、历史/恢复用户页面，包含 Usage 展示；不把排行榜作为 P0 用户主链路。
6. Session、Progress、Started、Completed、Result Artifact 与幂等。
7. 至少 1 个真实来源 Proof Run；主体验交付 3–4 篇完整赛事模拟知识 Run，至少三种明显不同的体验。模拟文章使用完整正文并标注“赛事模拟知识”；真实 Bounded Source Excerpt 仍必须显示覆盖范围且不得代表整篇文章。
8. 提交前公网部署、产品说明、开发日志和演示彩排。
9. Programability Gate：只有具备至少两种、均可回溯原文的程序原语才可编译；原语仅限可观察状态、原文分支、确定性评估、反馈回路、可重复实验、可保留结果物。普通线性步骤必须拒绝，不得换皮发布。
10. 三套引擎均为确定性 Schema Runtime：路径模拟只走有限、原文锚定的选择与状态迁移；微型实验只记录有限时段与反馈，不推导现实结论；规则沙盘只运行声明式白名单规则与有限参数。内部子模型不得改变这些边界。
10.1 Result 完成后允许用户主动请求“AI 结果解读”：只将本次有限填写、确定性 Result 与相关原文片段发送给已配置模型，用于解释、反思问题和提出一个可选的下一步。AI 输出必须显著标为“AI 辅助解读”，不得改变已生成的状态、路径、Started/Completed、Result Artifact 或原文锚点；不得将 AI 解释表述为文章原文结论或现实诊断。模型不可用时，确定性 Run 与 Result 必须完整可用。
11. 发现页可展示已人工发布的真实知乎 Run 与赛事模拟知识 Run。模拟内容统一标注“赛事模拟知识”，使用完整的模拟原文、规则和交互结果；不得称为官方接口返回的真实正文。卡片展示标题、作者、用途、预计时长、关键节点、来源范围、Started 与 Completed；Started 仅在首次有效交互后增加，Completed 仅在满足 Schema 完成条件后增加。
12. 发布失败、模型输出无效、Schema/Anchor/Semantic 校验失败时必须拒绝或留在内部草稿；不得自动降级为泛化任务清单并公开发布。

## 明确不做

公开编译页、完整 Admin UI、社交、评论、推荐、积分/金币/打卡式游戏化、排行榜入口、模型控制的运行路径、无边界 Runtime Chat、任意代码生成、产品内 Generic LLM Baseline、企业级基础设施。OAuth 不属于 P0；仅作为不阻塞主流程的可选 P1 登录能力。

## 内容接入边界

- 正文可由已配置的知乎官方内容接口自动读取：赛事知识池，或当前 Access Secret 所属账号的创作分析全文接口；赛事演示也允许使用完整的模拟知乎知识原文。
- 不提供粘贴正文、上传文件、填写任意文章链接、网页抓取或让用户导入第三方内容的入口。
- “我的知乎创作”仅自动列出当前授权账号已发布的内容；选择一篇后由服务端重新读取该篇完整正文，不能由前端传入正文。赛事模拟知识由受控预置数据提供，不提供用户正文导入入口。
- Run 内为完成确定性规则所收集的最少状态、选择或参数，不属于内容导入，默认仅在本地或受控进度中处理。

## 验收

- Hero 在移动端从发现到 Result 完整跑通，无登录阻塞；OAuth 若未配置不影响 Run。
- 每个关键 Action 能定位并高亮真实原文；错误 quote 或 offset 必须拒绝发布。
- Runtime 断开 LLM 后仍可完成。
- 用户可在 Result 后主动请求 AI 辅助解读；其输出与确定性 Result 分区展示，并不会改变路径、计数或来源证据。
- 第一次有效交互只计一次 Started；重复 Complete 返回同一结果。
- Result 仅汇总 Schema 与 Progress，不生成现实结论或新建议。
- 每个 Published Run 的组件和 Result 类型由 Source 与 Grammar 决定；禁止强制所有文章使用同一种表单。
- Inspect 必有“可观察状态 + 确定性评估”；Diagnose 必有原文支持的分支；Mission 必有状态及分支或结果物；Practice 必有反馈/实验及状态或结果物。所有 required Action 都必须触发声明的状态迁移。
- 所有七种运行模型在开发 fixture 中可独立完成并产生相应 Result；没有适合真实 Source 时必须保持未发布，不得伪造内容来凑模型数量。
- Bounded Source Excerpt 只能生成覆盖范围内、语义完整且可逐项锚定的动作；页面必须持续显示“基于官方接口可用片段生成”和字符覆盖范围，禁止出现“整篇已编译”等表述。
- Search 的摘要、description、introduction 与模型补写永远不能作为 Bounded Source Excerpt；本人创作列表的摘要也不能进入 Compiler，必须经创作分析接口读取完整正文。
- `contains_any` 不得产生确定性命中；需要用户输入时只保留最少字段，并默认本地处理。
- 至少一条真实来源完成自动编译与人工预览；四篇赛事模拟知识 Run 具有完整原文、可定位依据、不同输入导致的不同状态与不同 Result。
- 公网链接在提交前通过异网验证；产品说明和 Demo 与实现一致。

## 唯一待验证项

真实内容池能否提供至少两种可稳定编译的 Grammar。若某一题材不适合，不得强行套用固定场景；应保留其原始知识意图，并在 Inspect、Mission、Diagnose、Practice 中选择最贴合的程序形态。

## 可选 P1：知乎账号 OAuth

- 能力范围：账号授权、服务端会话、`GET https://openapi.zhihu.com/user` 基础资料。
- 不进入 Source Provider，不改变 Run 的编译与运行逻辑。
- App Key 与 OAuth Token 仅服务端保存；回调必须使用公网 HTTPS `/auth/callback` 并校验 `state`。
- 未部署或未配置凭证时，页面显示“部署后可用”，不得阻塞演示。
