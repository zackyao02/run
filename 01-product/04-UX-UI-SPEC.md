# UX UI Spec V1.6

## 体验原则

- 移动端优先，打开后 3 秒内出现可操作内容。
- 首屏先说“这能帮我做什么”，不先解释 Compiler 或 Runtime。
- 每个关键操作附近提供“查看来源”，但不打断主流程。
- 状态反馈先本地显示，再异步保存；失败时明确可重试。
- 不依赖颜色单独表达正常、风险与未确认。

## 页面

### 发现

只展示已发布 Run。Hero 卡片置顶，包含任务、预计时间、来源作者和“开始自检”按钮。P0 搜索只查本地 Published Run。

### 内容生产（仅内部）

内容操作台只展示系统自动同步的来源：赛事知识池，或当前授权账号自己的知乎创作。操作员只能选择来源、发起编译、预览和发布；不出现粘贴正文、文件上传、任意链接输入或抓取开关。这个页面不属于公开产品体验。

### Run 详情

解释适用对象、会得到什么、预计时间、来源文章与作者。主按钮是“开始运行”或“继续上次进度”。

### 运行

一次聚焦当前区块；持续显示“已确认 N / M”。Inspect 使用正常、风险、暂不确定三态。Diagnose 只显示当前问题与原文支持的选项。

### 来源证据

底部抽屉展示原文标题、作者、对应段落与 quote 高亮，并提供原文链接。找不到锚点的 Action 不能发布。

### Result

展示本次确认状态的分布与仍未确认的项目；允许回到对应步骤。文案只能描述本次运行，不声称现实结果已经达成。

### 历史与恢复

匿名设备身份即可使用。展示进行中与已完成 Session；OAuth 不属于 P0。

## Hero 体验预算

- 前 20 秒：进入 Hero 并完成第一次有效交互。
- 20–90 秒：标记至少一项风险并查看原文。
- 90–150 秒：完成剩余演示步骤并生成 Result。
- 150–180 秒：展示 AI 编译证据与知乎价值。

## 不做

排行入口、公共编译入口、正文导入、聊天框、复杂筛选、积分徽章、连续打卡、社交分享流和完整 Admin 页面。
