# Run Program Model Catalog V1.10

每种模型都是同一个 Source-bound Runtime 的不同呈现，不是不同产品，也不是按“职场文章 / 学习文章”预设的模板。编译期必须先从文章本身找到对应的结构证据，再选择唯一模型；没有结构就拒绝，不降级成清单。

| 模型 | 适用原文结构 | Runtime 产物 | 必须具备 |
|---|---|---|---|
| 情境模拟器 | 有限事件、回应与后续路径 | 行动轨迹 + 状态变量 | 原文分支、至少两个状态变量 |
| 诊断路径图 | “如果…则…”判断条件与落点 | 判断路径 + 当前节点 + 证据缺口 | 原文条件分支 |
| 微型实验室 | 实践时段、观察与下一轮调整 | 实验记录 | source-bound timer + 反馈或实验原语 |
| 规则压力测试器 | 可判断的结构规则 | 命中/缺口报告 | 白名单确定性评估 |
| 行动编排器 | 前置条件、解锁或补救关系 | 可恢复行动地图 | 状态 + 分支或结果物 |
| 对话排练器 | 明确的有限话术逻辑 | 对话轨迹 | 原文回应分支；无运行时 LLM |
| 参数沙盘 | 有限数量、范围或资源条件 | 当前配置与状态变化 | 声明式有限参数值 + 规则 |

## 共同硬规则

1. 每个关键事件必须有 Source Anchor。
2. 每个 required Action 必须触发一个声明的状态迁移。
3. Runtime 只能回放 Schema；不调用 LLM、执行表达式或生成下一步。
4. 变量 effect 是有限数值 delta，受 `min/max` 截断；不是脚本能力。
5. 真实内容必须通过 Source Scope、Programability、Anchor、Semantic 与人工 Preview 才能发布。
6. 开发 fixture 用于验证模型能力，永远不能作为真实 Hero 或 Supporting 内容。
