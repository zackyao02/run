# Competitive Differentiation

> 本文是外部产品定位研究，不属于官方赛事规则。

## 1. 知乎第二现场

公开项目核心是：
- 从知乎内容进入；
- 协商“这次先做什么”；
- 产生最小动作；
- 执行后判断继续聊/做/见/不继续；
- 强调“内容之后的下一步”。

Run 的区别：

```text
第二现场：
Content + Context
→ Negotiation
→ One-off Next Action

知乎 Run：
Content
→ Compile
→ Stable Executable Knowledge
→ Many Sessions
→ Usage Trace
```

一句话：
**一个是 Action Agent，一个是 Knowledge Compiler。**

## 2. ZHIHU://VERSE

公开项目把知乎搜索、直答、热榜、个人内容等组合成知识宇宙、小游戏、图谱、跑酷等 9 类互动实验。

它证明：
> “把知乎 API 做成交互体验”本身已经不能单独构成 Run 的创新。

Run 必须坚持：
- 不是 API Playground；
- 不是多玩法集合；
- 是“一个知识对象获得可执行版本”。

## 3. Generic App Builder

通用 App Builder 的核心通常是：

```text
Prompt / Requirements
→ Generate New App
```

Run：

```text
Existing Source
→ Grounded Compile
→ Executable Version
```

差异不是 UI 生成能力，而是 **Source Semantics + Usage Ownership**。

## 4. Document → Workflow

企业文档转 Workflow 与 Run 在“文本变流程”上接近，但 Run 的核心对象是社区知识：
- 保留作者/source；
- 用户直接消费；
- Usage 回到知识对象；
- 不把企业 SOP 当中心场景。

## 5. 防撞结论

如果去掉以下任意两项，Run 会迅速退化成普通项目：
- Existing Knowledge Object
- Source-bound
- Stable Runtime
- Versioned Schema
- Usage Trace

因此这五项属于产品不可拆核心。
