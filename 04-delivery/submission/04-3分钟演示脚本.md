# 知乎 Run｜3 分钟演示脚本与分镜

## 演示目标

让评审在 20 秒内理解：这不是 AI 再回答一次，而是把知乎知识变成一套能执行、能回看、能留下结果的程序。

| 时间 | 画面 | 讲解词 | 操作 |
| --- | --- | --- | --- |
| 0:00–0:20 | 首页 Hero 与知识卡片 | “我读过很多知乎方法，但真正照着做时容易漏步骤。知乎 Run 把文章编译成可以逐步执行的程序。” | 选择 Hero，点击 RUN |
| 0:20–0:45 | 编译动画与运行页 | “这不是重新生成任务清单，而是加载这篇文章专属的规则、分支和结果物。” | 等待编译动画结束 |
| 0:45–1:30 | 第一、第二步运行卡片 | “我把自己的真实情况带进来；每次选择都会改变状态或路径。” | 完成 1–2 个有效输入 |
| 1:30–1:55 | 原文依据抽屉 | “这里可以直接回到文章原句，看到这一步为什么存在。” | 点击“查看原文”并展示高亮片段 |
| 1:55–2:20 | Result 页面 | “完成后得到的是本次运行的结果物，不是对现实的夸张承诺。” | 完成剩余步骤，展示 Result |
| 2:20–2:40 | AI 辅助解读 | “如果我需要个性化理解，再主动请求 AI。它只解释本次填写、结果和相关原文，不改写程序结果。” | 点击 AI 辅助解读 |
| 2:40–3:00 | 回到首页或展示第二篇 Run | “同一套引擎可以承载不同文章，但每篇文章的程序形态由原文决定。” | 快速打开另一篇知识卡片，收束产品价值 |

## 现场讲解要点

- 不现场编译真实文章，优先演示已经验证的 Published Run。
- 不把赛事模拟知识说成官方真实正文。
- 不承诺 AI 诊断现实问题；强调它是结果后的辅助解释。
- 如果网络异常，继续演示已发布 Run 的确定性流程。

## 备用视频结尾

“知乎 Run 让知识不止被收藏，而是被运行；让每一步都知道来自哪里，完成后还能留下什么。”
