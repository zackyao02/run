# 知乎 Run｜产品说明计划书

## 1. 产品定位

知乎 Run 面向已经读过一篇方法型知乎内容、准备真正照着做的人。它解决的不是“没有答案”，而是读完之后容易忘记步骤、遗漏条件、无法留下过程证据的问题。

> 普通 AI 再回答一次；知乎 Run 把原知识编译成一个可重复运行、每一步能回到出处的版本。

## 2. 用户痛点

- 文章里的方法散落在长文中，执行时需要反复翻找。
- 用户的现实情况不同，照抄统一清单往往不适用。
- AI 临时生成的建议难以确认是否忠于原文。
- 做完之后没有稳定的过程记录和可复查结果。

## 3. 核心体验

`阅读知识 → 点击 RUN → 填入真实情况 → 按原文规则推进 → 查看原文依据 → 获得 Result → 可选 AI 解读`

每篇文章不是一张静态任务清单，而是一套由文章规则决定的互动程序：有限选择会改变状态，输入会形成结果物，完成后可以回看每一步对应的原文。

## 4. AI 在哪里发挥作用

### 发布前

服务端 AI 判断内容是否适合交互化，规划最贴合原文的运行结构，把文章编译成受限 Schema，并为每个关键动作建立原文锚点。Schema、语义和锚点校验不通过时不会发布。

### 运行后

用户主动点击“AI 辅助解读”后，系统只发送本次有限填写、确定性 Result 和相关原文片段。AI 用于解释、反思和提供一个可选下一步，不改变状态、路径、计数、结果物或原文依据。

### 为什么运行时不用 AI

运行时采用确定性 Schema，保证同样的输入得到可复查的路径和结果；即使网络或模型不可用，已发布知识仍然可以运行。

## 5. 技术方案

```text
官方可验证知识来源
  → AI Judge / Planner / Compiler
  → Schema + Source Anchor 校验
  → 人工 Preview / Publish
  → 确定性 Runtime
  → Session / Progress / Result / Usage
```

产品层提供路径模拟、微型实验、规则沙盘三套运行引擎。每个 Run 只使用原文确实支持的状态、分支、评估、反馈、实验或结果物。

## 6. 知乎生态价值

- 让优质方法型内容从“读过”进入“做过”。
- 保留作者原文、来源范围和关键语句，增强知识可信度。
- 通过稳定 Run 让用户带走结果物，而不是一次性聊天文本。
- 为未来作者创作分析、内容编译和知识服务提供可扩展的产品形态。

## 7. 真实性与安全

- 官方 Run 与赛事模拟知识明确分开标识。
- 范围有限的官方片段持续披露字符覆盖范围，不声称代表整篇文章。
- App Key、Token、模型密钥只在服务端保存。
- 不提供任意正文粘贴、网页抓取或第三方文章导入入口。
- Result 只表达本次程序状态，不冒充现实诊断或现实承诺。

## 8. 评审时希望看到的三个瞬间

1. 一篇文章点击 RUN 后，整篇知识被理解为一套可操作程序。
2. 用户的真实输入改变了状态、路径或结果物，并能点回原文依据。
3. 完成后得到稳定 Result；AI 解读是可选的、受边界约束的辅助层。
